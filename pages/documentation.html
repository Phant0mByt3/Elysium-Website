Site Documentation

Notes for whoever edits this site next — including future you.

Folder structure

/index.html        Main entry point (required by GitHub Pages)
/pages/            Secondary static pages (this file lives here)
/css/style.css     Design tokens, layout, and all component styling
/css/animations.css  Keyframes and motion-only effects
/js/main.js        All page interactions (nav, reveals, map, gallery, easter eggs)
/js/particles.js   Canvas particle field used behind the hero
/data/dev-stages.json  Development stage manifest (see below)
/assets/           Reserved for audio or downloadable files
/images/           Reserved for real screenshots and art once available

Development stages bar

The Development section on the homepage renders a "Development Stages" widget: one collapsible bar per workstream (Documentation, Concept Art, World, Lore, Gameplay Systems, Economy, Technical, Music, Factions, Systems & Progression, Marketing & Devlog), and inside each one, a tiny tile for every individual piece of work in that stage — pulled from data/dev-stages.json.

  • The file is one object with a top-level stages array. Each stage looks like { "id": "world", "label": "World", "blurb": "...", "items": [ ... ] }.
  • Each item inside a stage's items array looks like { "id": 101, "title": "World 001 — Region Layout", "done": true }.
  • If done is true, that item renders as a filled gold tile and counts toward both that stage's percentage and the page-wide total. If false, it renders as a hollow tile.
  • Click a stage's header to expand it and reveal its tiles — they're built and animated in the first time you open that stage, so the page stays light even with hundreds of pieces across all stages.
  • To add a piece of work, append a new object to the relevant stage's items array. To add a whole new stage, append a new object to the top-level stages array with its own id, label, blurb, and items. No code changes are required — bars, tiles, and totals rebuild themselves from the JSON.
  • Flip an item's done value to true the moment that piece is actually finished, so the bars stay honest.
  • This fetch requires the page to be served over http(s) (a local server or GitHub Pages) — opening index.html directly as a file:// URL will block the request in most browsers.

Replacing placeholder art

Every image on the site is currently an inline SVG gradient so the project has zero binary dependencies. To swap in real screenshots or concept art:

  • Drop files into /images/ using descriptive names, e.g. images/screenshots/aurelia-dawn.jpg.
  • In js/main.js, the gallery() block builds each tile from the items array — replace the generated SVG with an <img> tag pointing at your file.
  • For the world map and continent cards, swap the inline <svg> blocks in index.html for background images or <img> elements using the same relative paths.

Adding ambient audio

The audio control in the bottom-left corner is wired up but silent by default. Add a licensed track to /assets/audio/, then uncomment the <source> tag inside the #ambient-audio element in index.html.

Deploying to GitHub Pages

Push this folder to a repository, then enable Pages in the repository settings pointing at the root of the default branch. Because every path in the project is relative, no build step or base-path configuration is required.
