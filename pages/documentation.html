Site Documentation

Notes for whoever edits this site next — including future you.

Folder structure

/index.html        Main entry point (required by GitHub Pages)
/pages/            Secondary static pages (this file lives here)
/css/style.css     Design tokens, layout, and all component styling
/css/animations.css  Keyframes and motion-only effects
/js/main.js        All page interactions (nav, reveals, map, gallery, easter eggs)
/js/particles.js   Canvas particle field used behind the hero
/data/dev-stages.json   Development stage manifest (see below)
/data/classes.json      Playable classes shown in the Classes section
/data/factions.json     Major + joinable factions, reputation copy
/data/professions.json  Crafting/gathering professions list
/data/features.json     Core feature grid + world boss showcase
/data/expansions.json   Player-facing "Expansion Roadmap" cards
/data/continents.json   Launch continents, future expansion territories, and world-map marker coordinates — one file, since the World section, the mini expansion strip, and the interactive map all describe the same regions
/data/gallery.json      Gallery tiles (label, category, placeholder gradient)
/data/lore.json         The full lore "book" — ages, chapters, notable figures. Powers both the homepage timeline summary and pages/lore.html
/pages/lore.html   Full lore book, rendered from data/lore.json
/assets/           Reserved for audio or downloadable files
/images/           Reserved for real screenshots and art once available

Everything is JSON-driven

Every section listed above under /data/ works the same way: index.html contains an empty container with an id (e.g. #class-grid) and a data-loading="…" hint, and the matching function in js/main.js fetches the JSON file and builds the markup at runtime. This means updating game content — adding a class, renaming a faction, adding a continent — is a JSON edit, not an HTML edit. If a fetch fails (most commonly because the page was opened as a local file:// file instead of being served), the container shows a short explanation instead of staying silently blank.

  • Classes — edit data/classes.json. Each entry needs id, name, archetype, patron, role, description, icon (an SVG path string) and a stats object with power, defense, magic, difficulty (0–100).
  • Factions — edit data/factions.json. Split into major and joinable arrays, plus reputationScale, reputationNote, and allianceNote for the copy beneath the cards.
  • Professions — edit data/professions.json: a flat professions array of id, name, description, icon.
  • Core features & world bosses — edit data/features.json: a features array (the numbered grid) and a worldBosses array (set "variant": "void" for the purple/void styling).
  • Expansion roadmap cards — edit data/expansions.json.
  • Continents & expansion territories — edit data/continents.json. launch entries render as the big continent cards and a map marker; expansionTerritories entries render as the mini "Future Expansion Territories" strip and a "future" map marker. Each needs a map: { x, y } coordinate pair (SVG viewBox is 900×420) and a modalBody/modalTitle shown when its map marker is clicked.
  • Gallery — edit data/gallery.json. Each item needs id, label, type (must match one of the filter tabs' data-filter values) and a two-color gradient used to generate its placeholder art.
  • Lore — edit data/lore.json. See the dedicated section below.

Development stages + roadmap (combined)

The Development section used to show three overlapping progress indicators — a "Development Status" summary of four hand-set percentages, a detailed "Development Stages" checklist, and a separate Phase 1–4 roadmap bar hard-coded to 50%. The summary block has been removed, and the other two are now one panel: the Phase roadmap's fill line is driven by the same real completion percentage computed from data/dev-stages.json, instead of a number someone has to remember to update by hand.

  • The file is one object with a top-level stages array. Each stage looks like { "id": "world", "label": "World", "blurb": "...", "items": [ ... ] }.
  • Each item inside a stage's items array looks like { "id": 101, "title": "World 001 — Region Layout", "done": true }.
  • If done is true, that item renders as a filled gold tile and counts toward both that stage's percentage, the page-wide total, and the roadmap fill line beneath the checklist. If false, it renders as a hollow tile.
  • Click a stage's header to expand it and reveal its tiles — they're built and animated the first time you open that stage, so the page stays light even with hundreds of pieces across all stages.
  • To add a piece of work, append a new object to the relevant stage's items array. To add a whole new stage, append a new object to the top-level stages array with its own id, label, blurb, and items. No code changes are required.
  • Flip an item's done value to true the moment that piece is actually finished, so the bars — and now the roadmap line too — stay honest.
  • This fetch requires the page to be served over http(s) (a local server or GitHub Pages) — opening index.html directly as a file:// URL will block the request in most browsers.

The hero title fix

The hero title's letter-by-letter reveal used to fire almost immediately on page load, which meant the entire animation ran and finished behind the still-opaque loading screen — by the time the loading screen faded, the title either popped in fully formed with no visible animation, or (if any earlier script threw) never got its reveal class added at all. The reveal is now triggered from the same callback that hides the loading screen, so it only plays once it's actually visible. If JavaScript never runs at all, the title still displays normally: it's the letter-splitting step (not the base markup) that the animation depends on, so an unsplit title just renders as plain gradient-filled text with no animation, rather than staying invisible.

Replacing placeholder art

Every image on the site is currently an inline SVG gradient so the project has zero binary dependencies. To swap in real screenshots or concept art:

  • Drop files into /images/ using descriptive names, e.g. images/screenshots/aurelia-dawn.jpg.
  • In js/main.js, the gallery() block builds each tile from data/gallery.json — replace the generated SVG with an <img> tag pointing at your file, or add an image field to the JSON and branch on its presence.
  • For the world map and continent cards, the same applies to data/continents.json and the worldContinents() block.

Lore book (pages/lore.html)

The homepage's Lore section is a short scroll-driven summary of the four ages. pages/lore.html is the full book, rendered entirely from data/lore.json:

  • title, subtitle, and foreword — the page header and italic intro paragraph.
  • ages — an array of eras. Each needs id (used as the anchor/table-of-contents target), era, title, summary, and a chapters array of { heading, body }, where body is an array of paragraph strings.
  • figures — an appendix grid of notable characters, patrons, and bosses: { id, name, title, description }.
  • Add a new age, chapter, or figure by editing the JSON — the table of contents, headings, and figure grid all rebuild automatically.

Adding ambient audio

The audio control in the bottom-left corner is wired up but silent by default. Add a licensed track to /assets/audio/, then uncomment the <source> tag inside the #ambient-audio element in index.html.

Deploying to GitHub Pages

Push this folder to a repository, then enable Pages in the repository settings pointing at the root of the default branch. Because every path in the project is relative, no build step or base-path configuration is required.
